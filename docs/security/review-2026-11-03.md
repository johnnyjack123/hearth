# Sicherheitsprüfung vor 1.0 (3.11.2026)

Statische Prüfung des Stands `d0db4f2` durch einen eigenen Agenten (nur Lesen, nichts gebaut oder ausgeführt). Ergebnis: 3 hohe, 8 mittlere, rund 20 niedrige Funde. Kein Weg, Code aus dem Container direkt auf dem Host auszuführen; aber vier Wege um die Hauptschutzmechanismen. Der Bericht unten ist der des Prüfers (Englisch), Stand und Abarbeitung stehen in `docs/ROADMAP.md` („Weg zu 1.0“).

## High

**H1. Every project mounts pi's config volume read-write, so one hijacked project reaches all the others.**
`crates/harness-core/defaults/harnesses/pi.toml:13` (`persist = ["~/.pi"]`), `config/model.rs:472` (one volume `harness-cfg-pi` per harness, not per project), `instance.rs:132-141`.
- A hijacked agent in project A reads and edits the pi sessions of every other project's chats (planted turns; harness does not resend history to a non-empty session), adds `models.json` entries, reads the user's own pi logins.
- If pi auto-loads `~/.pi/agent/extensions/*.ts` or `AGENTS.md` (pi's documentation; not checked against the installed version), its code runs inside project B, possibly with network Off, and can copy B's workspace into the shared volume.
- Fix: one config volume per project, or copy only the needed read-only parts in.

**H2. The merge review can be blinded or sidestepped, and autosync merges anything without a High finding.**
- `takeover.rs:156-164` holds a merge only on a High finding.
- `HostRepo::incoming` (`sync/host.rs:494-536`) diffs with the working tree's attributes; the `.gitattributes` rule (`review.rs:276-291`) only matches `filter=`, `diff=`, `merge=`. A committed `* -diff` or `* binary` raises nothing, and from then on every file diffs as binary; content rules, OSV and Jev skip binary files (`review.rs:61-64`, `harness-cli/src/review.rs:181`).
- Evasions: the install-script rule (`review.rs:347-352`) only fires when `"postinstall"` starts a line (one-line JSON or `\u0070ostinstall` passes); a patch over 32 MB stops content checks (only Medium `too-large`, `review.rs:66-78`); hooks under a repo's own `core.hooksPath` are missed (`review.rs:143-148`).
- Not checked at all: `.claude/settings.json` (hooks), `.mcp.json`, `AGENTS.md`/`CLAUDE.md`, `.lfsconfig`, `desktop.ini`/`.url`/`.scf`.
- Fix: diff with `--text` and `--attr-source=<empty tree>` (or blank `core.attributesFile`), parse `package.json` as JSON, make truncation and the new categories High during automatic merges.

**H3. Research mode's "found URL" check lets a hijacked model send chat data out without any approval.**
`apps/server/src/websearch/known-urls.ts:38-40,90-93`, used at `webfetch/tool.ts:346`. `has()` accepts a URL when every `name=value` pair is in the set of pairs of any found URL with the same page key, order and repetition ignored. A page links `https://x.example/c?a=&b=&…&z=&0=…`; injected text makes the model load `…?s=&e=&c=&r=&e=&t=…`, spelling out chat data one character per pair, without an approval card. Agents use the same check (`hub.ts:530-541`), only search hits count there. Fix: accept only the exact URL plus scheme, `www.` and trailing-slash variants; drop only known tracking parameters.

## Medium

**M1. The LLM pass-through lets agents bypass the network rules through provider-side tools.** `apps/server/src/routes/llm.ts:53-60,270-283`: body and `anthropic-beta`/`openai-beta` headers pass unchanged; Anthropic `mcp_servers`/web fetch, OpenAI Responses `{type:"mcp", server_url}`, Gemini `url_context` make the provider connect to an attacker host. `.all()` (`llm.ts:245`) allows any method on allowed paths (e.g. `DELETE …/models/ft:…`, `GET chat/completions`). Fix: strip or reject server-side tool types for device requests, allow-list beta header values, one method per path.

**M2. Agent- and chat-written memories act as a persistent prompt injection.** `llm.ts:203-227`, `services/memories.ts:42-51`: any agent can `remember` text that reaches every later chat and agent; the eight-pattern filter passes ordinary-looking instructions; agents can `forget` the user's memories. Fix: keep `agent`/`chat` memories pending until confirmed in the web app, or scope them to their project.

**M3. Git LFS (or any filter driver in the user's global/system git config) runs on the host during `git merge`.** `sync/host.rs:538-563` overrides nothing for `filter.*`; merges at `:401`, `:415`; `.lfsconfig` is not reviewed. Fix: `GIT_LFS_SKIP_SMUDGE=1`, blank configured `filter.<name>.*` with `-c` during merges, make `.lfsconfig` and `filter=` High.

**M4. One stray keystroke in the terminal can answer a gateway question, including "always".** `harness-cli/src/terminal/session.rs:299-331,336-361`, keys in `net.rs:586-600`. Fix: drain input when the prompt shows, ignore keys for about a second, require Enter, confirm "always" in a second step.

**M5. Slow regular expressions on fetched pages or uploaded documents can freeze the server.** `webfetch/convert.ts:333` (`/[ \t]+\n/` on a 2 MiB body of spaces), `convert.ts:213` (`HEAVY_BLOCKS`), `convert.ts:131` (title), `webfetch/sections.ts:60` (heading line padded with spaces). Fix: linear code, or `loadPage` in a worker with a time limit.

**M6. `/_documents`, `/_web/search` and the research auto-approval are scoped to the device, not to the project.** `llm.ts:231-237`, `tunnel/hub.ts:483-541`: an agent in project A reads documents of a chat running in project B on the same computer. Fix: the gateway adds a project identifier the agent cannot set; the server matches device and project.

**M7. Install-time network grants apply to the whole project, outlive the installer, and the agent can re-trigger them.** npm for 15 min (`instance.rs:296-301`), recipe hosts for 30 min (`apps.rs:246-258`) on the project's gateway; `harness_installed` (`instance.rs:264-281`) runs `sh` via the image PATH where agent-writable `~/.local/bin` comes first (`images/base/Containerfile:81`). Fix: `/bin/sh` by absolute path, grants scoped to the installer container and revoked afterwards.

**M8. Another local Windows account can plant `C:\ProgramData\llm-harness` before install and later make SYSTEM run its code.** `harness-cli/src/vmd.rs:953-1002,1023-1051`. Shared PCs only, before the first install. Fix: refuse an existing folder not owned by SYSTEM/Administrators or containing reparse points; create it with a protected security descriptor; check at service start.

## Low

- Browser-supplied paths in `apps.file` (`app.rs:273-279`, `app_file.rs:77-101`, `connect.rs:773-793`): UNC paths (NTLM to any SMB host), file existence and size leak, raw title/path in the terminal.
- `merge --approve` merges by branch name, not by the pinned commit (`takeover.rs:284-340`).
- The elevated install copies `harness-vmd.exe` from the user's folder without a hash check (`vmd.rs:502-521,1012`).
- SYSTEM runs `Optimize-VHD` on a path inside the user's profile (`harness-vmd/src/machine.rs:96-112,599-634`); junctions could redirect it (lossless).
- vmd pipe: the CLI does not check who serves it (`harness-core/src/vmd.rs:158-190`); the user's `GRGW` includes create-instance rights (`pipe.rs:31`); answers printed unsanitized.
- Gateway approvals keyed by a counter restarting at 1; grants ignore the port (`harness-gateway/src/gateway.rs:118,163-179,402-405`; `hub.ts:629-635`).
- The gateway drops framing headers listed in `Connection:` (`http.rs:293-308`); never drop `content-length`/`transfer-encoding`.
- The per-file CSP sandbox is overwritten by the global `secureHeaders` (`routes/files.ts:96,109` vs `app.ts:48-63`).
- Banned users keep working device tokens (`services/devices.ts:438-461`).
- Auth/pairing: `X-Forwarded-For` trusted when 8080 is reached directly; first account admin and open registration by default; `/api/pairing` without body limit and a global cap of 50 pending pairings; the approval page shows only the device's chosen name.
- `server-secret` content not length-checked (`config.ts:130-134`).
- Untrusted text loses its data framing: a document can close `<file>…</file>` (`files/model.ts:20`); compaction summaries go into a user message (`compact.ts:283`).
- The calculator worker runs in the server process (`calculator/engine.ts:158-215`).
- markitdown (`apps/markitdown/server.py:60-66,124-130`): no memory limit, bodies read before the concurrency limit, shared uid and `/tmp`, only the direct child killed on timeout.
- IPv6 addresses in the own LAN prefix count as public (`webfetch/address.ts:93-104`, `address.rs`).
- Web app: model output can embed images from any URL; Streamdown's `harden` allows every image prefix (`markdown.tsx:61-70`), only the CSP `img-src 'self' data: blob:` blocks it (not in Vite dev); the image download button falls back to `window.open(src)`.
- `--userns=keep-id` (`podman/args.rs:64`): an escape lands as the VM user owning every volume.
- `sync::sanitize` (`sync/mod.rs:444-454`) leaves bidi and zero-width characters in paths of review reports.
- Default `llm_apis = ["api.deepseek.com"]` (`defaults/config.toml:17`) stays directly reachable in every preset.
- Releases unsigned, no checksums, `install.ps1` accepts an `http://` ZIP, Actions pinned by tag.

## Checked and sound

Gateway address filter (all private/special ranges incl. IPv4-mapped, NAT64, 6to4, Teredo; resolved addresses dialed exactly, no rebinding); gateway request handling (`safe_path`, `/_web/known` unreachable for agents, credential headers stripped, no header folding, CONNECT bound to `llm.harness`); control socket permissions, token via stdin, TLS name checks, gateway container as nobody; container hardening (unconditional flags, internal networks only, no host mounts, validated names, `copy_out` limits); `HostRepo` (hooks, fsmonitor, submodules off, `fsckObjects`, `GIT_*` removed, fast-forward CAS imports); approvals never from browser or container; device tokens never on user routes; CSRF exemptions bearer-only; ownership checks on every `:id` route; 256-bit pairing tokens hashed; strict tunnel validation; AES-GCM with associated data; Kysely only; static serving without traversal; server-side fetch (parsing, pinned DNS, re-checked redirects, limits); uploads typed by content; vmd environment, `vmd.toml` validation, PowerShell values via environment, pipe protocol, quoted service path; tray approvals local only; web app without `dangerouslySetInnerHTML`, raw → sanitize → harden, safe links, Mermaid strict, KaTeX untrusted, CSP `script-src 'self'`.

## Not reviewed
